## Installation boundary

Machine-local `C:\Users\Wiryl\.codex-ensemble` is generated executable state, never authority. It must eventually be installed from one exact admitted Ryladmin commit plus local non-secret executable/tool provenance.

The current `recovery/templates/runtime/` tree predates this ownership transition and remains a generic replacement-machine recovery template. It is **not** the canonical current runtime and must not overwrite the surviving commissioned runtime merely to make paths look uniform.

A later Q-ADMIN-03 portability/install package must reconcile the generic recovery renderer to `runtime/current/`, prove deterministic rendering on a disposable target, and only then retire or redirect the older templates.

## Candidate and self-modification law

The currently commissioned runtime must judge any successor from outside the candidate installation. Runtime changes are prepared in an isolated Ryladmin worktree, deterministically audited, reviewed using the old admitted runtime, merged, then installed into a separate or rollback-safe target and revalidated before becoming active. Candidate code may not overwrite the active runtime before that sequence completes.

`verify-source.ps1` deterministically verifies the canonical file set, byte hashes, private-state exclusion, PowerShell parsing, and optionally installed-runtime byte identity.

`CURRENT_SOURCE_MANIFEST.json` is a source-integrity manifest, not a credential store or machine authorization. It records the exact Project policy ref, admitted Codex identity, file hashes/byte counts, exclusions, and source status. Replacement-machine execution still requires local tool/auth/path/connector revalidation.

Native subagents remain disabled in this source snapshot. Q-ADMIN-03 MA-01 is the first gate allowed to propose a multi-agent runtime successor.
